ANGGOTA 1 — ITQON EL FIKRY FAUSTA | Modul: BST Katalog Buku
================================================================

[SESI 1 — Pemahaman Konsep BST]

[Claude Sonnet 4.6]
PROMPT:
"Bisa jelasin konsep Binary Search Tree secara singkat?
Terutama kenapa kuncinya harus unik dan bagaimana cara
kerjanya buat pencarian data."

RESPONS (ringkasan):
BST adalah pohon biner di mana setiap node punya kunci unik.
Node kiri selalu lebih kecil dari root, node kanan selalu
lebih besar. Pencarian efisien karena di setiap langkah,
setengah dari pohon bisa diabaikan — sehingga O(log n)
untuk kasus rata-rata.

----------------------------------------------------------------

[Claude Sonnet 4.6]
PROMPT:
"Kalau datanya dimasukkan dalam urutan terurut dari kecil
ke besar, apa yang terjadi dengan bentuk pohonnya?"

RESPONS (ringkasan):
Jika data diinsert secara terurut, BST akan menjadi miring
ke satu sisi (degenerate tree), sehingga tinggi pohon = n
dan semua operasi menjadi O(n) bukan O(log n).
Ini disebut worst-case BST.

----------------------------------------------------------------

[GPT-5.5]
TANYA:
"class BSTNode itu sebenernya buat apa ya? apa bedanya
sama class BSTKatalog?"

JAWAB (ringkasan):
BSTNode adalah blueprint satu node dalam pohon — menyimpan
data buku dan pointer ke anak kiri/kanan. BSTKatalog adalah
manajer pohon secara keseluruhan yang menyimpan root dan
menyediakan operasi insert, search, delete. Analogi:
BSTNode = satu kotak, BSTKatalog = rak yang mengelola
susunan semua kotak.

----------------------------------------------------------------

----------------------------------------------------------------

[GPT-5.5]

JAWAB (ringkasan):
_insert_rekursif dipanggil dari dalam fungsi insert() —

----------------------------------------------------------------

[Claude Sonnet 4.6]
PROMPT:
"Gimana cara implementasi delete BST yang benar? Aku bingung
handle kasus node dengan dua anak."

RESPONS (ringkasan):
Tiga kasus delete BST:
1. Node daun: langsung hapus
2. Satu anak: ganti node dengan anaknya
3. Dua anak: cari inorder successor (node paling kiri
   di subtree kanan), salin datanya ke node yang dihapus,
   lalu hapus inorder successor dari subtree kanan.

----------------------------------------------------------------

[GPT-5.5]
TANYA:
"fungsi _cari_minimum itu gunanya apa di dalam delete BST?"

JAWAB (ringkasan):
_cari_minimum dipakai untuk menemukan inorder successor,
yaitu node dengan nilai terkecil di subtree kanan node yang
akan dihapus. Node ini dipakai sebagai pengganti node yang
dihapus ketika node tersebut punya dua anak, agar urutan
BST tetap terjaga setelah penghapusan.

----------------------------------------------------------------

[Claude Sonnet 4.6]
PROMPT:
"Kenapa inorder traversal BST menghasilkan data terurut?
Bisa jelasin urutannya?"

RESPONS (ringkasan):
Inorder mengunjungi node dengan urutan kiri -> root -> kanan.
Karena semua node kiri lebih kecil dari root dan semua node
kanan lebih besar, urutan kunjungan secara alami menghasilkan
data dari terkecil ke terbesar.

[SESI 3 — Analisis Big-O BST]

[Claude Sonnet 4.6]
PROMPT:
"Kalau 80 buku disisipkan dengan urutan ISBN-0001 sampai
ISBN-0080 secara berurutan, berapa tinggi tree yang
terbentuk? Bandingkan dengan urutan acak."

RESPONS (ringkasan):
Insert berurutan menghasilkan pohon linear setinggi n=80
(worst-case O(n)). Insert acak menghasilkan pohon dengan
tinggi mendekati log2(80) sekitar 6-7 level. Ini dasar
Pertanyaan Analisis no.1 di laporan.

----------------------------------------------------------------

[Claude Sonnet 4.6]
PROMPT:
"Kapan BST tetap lebih unggul dibanding Hash Table meski
Hash Table O(1) average untuk search?"

RESPONS (ringkasan):
BST unggul untuk: range query, data terurut otomatis via
inorder, operasi predecessor/successor, dan tidak ada
collision handling. Hash Table unggul hanya untuk point
query O(1) average.

Worst-case ruang dan waktu keduanya O(n) pada kondisi sama.

[SESI 1 — Pemahaman Konsep Graf]

[Claude Sonnet 4.6]
PROMPT:
"Apa perbedaan representasi adjacency list vs adjacency
matrix untuk graf? Mana yang lebih cocok untuk sistem
rekomendasi buku?"

RESPONS (ringkasan):
Adjacency matrix: O(V2) ruang, O(1) cek edge, boros untuk
sparse graph. Adjacency list: O(V+E) ruang, O(deg) cek edge,
efisien untuk sparse graph. Untuk rekomendasi buku (sparse),
adjacency list jauh lebih efisien.

----------------------------------------------------------------

[GPT-5.5]
TANYA:
"self.adj di GraphRekBuku itu isinya apa ya formatnya
gimana?"

JAWAB (ringkasan):
self.adj adalah dictionary dengan format:
{ isbn: [(isbn_tetangga, bobot), ...] }
Contoh: {'ISBN-0001': [('ISBN-0002', 3), ('ISBN-0003', 1)]}
Artinya ISBN-0001 pernah dipinjam bersama ISBN-0002
sebanyak 3 kali dan bersama ISBN-0003 sebanyak 1 kali.

----------------------------------------------------------------

[Claude Sonnet 4.6]
PROMPT:
"Gimana cara kerja BFS dan kenapa lebih cocok dari DFS
untuk rekomendasi dengan batasan hop?"

RESPONS (ringkasan):
BFS menjelajah level per level sehingga mudah dibatasi
dengan max_hop. DFS pergi sejauh mungkin ke satu jalur
dulu sehingga sulit dikontrol batasannya. Untuk rekomendasi
dengan batasan jarak 2 hop, BFS adalah pilihan tepat.

[SESI 1 — Pemahaman Queue dan Stack]

[GPT-5.5]
TANYA:
"class Queue di queue.py itu buat apa bedanya sama
list biasa Python?"

JAWAB (ringkasan):
Queue ini mengimplementasikan antrian FIFO berbasis Linked

----------------------------------------------------------------

[Claude Sonnet 4.6]
PROMPT:
"Apa perbedaan mendasar Queue dan Stack? Dan kenapa keduanya
lebih baik diimplementasi dengan Linked List daripada array
untuk kasus perpustakaan ini?"

RESPONS (ringkasan):
Queue = FIFO, cocok untuk antrian. Stack = LIFO, cocok
untuk undo. Linked List lebih baik karena tidak perlu
pre-allocate ukuran, insert/delete di ujung selalu O(1)
tanpa shift elemen, dan ukuran dinamis.

----------------------------------------------------------------

[Claude Sonnet 4.6]
PROMPT:
"Kenapa Queue perlu pointer tail selain pointer head?
Apa yang terjadi kalau tidak ada pointer tail?"

RESPONS (ringkasan):
Tanpa tail pointer, setiap enqueue harus traversal dari
head ke node terakhir = O(n). Dengan tail pointer,
enqueue langsung sambung ke tail = O(1).

----------------------------------------------------------------

[SESI 2 — Implementasi Queue]

[GPT-5.5]
TANYA:
"_head dan _tail di Queue itu nunjuk ke apa pas Queue
baru dibuat dan pas Queue kosong setelah di-dequeue semua?"

JAWAB (ringkasan):
Saat Queue baru dibuat: _head = None, _tail = None.
Saat ada elemen: _head nunjuk ke node terdepan (pertama

masuk). Saat Queue jadi kosong lagi setelah semua
di-dequeue: keduanya harus di-reset ke None. Kalau _tail
tidak di-reset, enqueue berikutnya akan nyambung ke node
lama yang sudah tidak valid.

Pointer tail tidak direset ke None saat queue jadi kosong.
Fix: tambahkan 'if self._head is None: self._tail = None'
setelah menggeser head di dalam dequeue.

----------------------------------------------------------------

[Claude Sonnet 4.6]

Kan Queue tidak support random delete."

RESPONS (ringkasan):
Rebuild: ambil semua elemen ke list sementara O(k), filter

[GPT-5.5]

paling atas tumpukan — node yang paling terakhir di-push
dan akan paling pertama di-pop.

PESAN -> hapus nim dari antrian ISBN tersebut.

[Claude Sonnet 4.6]

[SESI 1 — Pemahaman Algoritma Sorting]

[GPT-5.5]
TANYA:
"sorting.py itu dipanggil dari modul mana? dan fungsinya
buat apa di sistem perpustakaan ini?"

JAWAB (ringkasan):
sorting.py diimport oleh modul_5.py (ManajerLaporan).
Fungsinya untuk menyortir data laporan bulanan:
shell_sort_durasi mengurutkan riwayat peminjaman berdasarkan

Hasilnya ditampilkan saat perintah LAPORAN_BULAN di CLI.

----------------------------------------------------------------

[Claude Sonnet 4.6]
PROMPT:
"Apa perbedaan Shell Sort dan Merge Sort dari segi Big-O
dan kapan masing-masing lebih unggul?"

RESPONS (ringkasan):
Shell Sort: ~O(n^1.5) dengan gap sequence Knuth, in-place,
lebih cepat untuk data kecil atau hampir terurut.
Merge Sort: O(n log n) guaranteed, stable sort, butuh
memori tambahan O(n). Untuk laporan bulanan, keduanya
bisa dibandingkan runtimenya secara empiris.

----------------------------------------------------------------

[Claude Sonnet 4.6]
PROMPT:
"Kenapa Shell Sort lebih baik dari Bubble Sort atau
Insertion Sort biasa untuk kasus ini?"

RESPONS (ringkasan):
Bubble Sort dan Insertion Sort keduanya O(n2) worst-case.
Shell Sort memperbaiki ini dengan membandingkan elemen
yang jauh terlebih dahulu. Gap sequence Knuth
(1, 4, 13, 40...) memberikan kompleksitas ~O(n^1.5).

----------------------------------------------------------------

[SESI 2 — Implementasi Sorting pada Linked List]

[GPT-5.5]
TANYA:
"nodes = [] di shell_sort_durasi itu buat apa? kenapa
perlu dikumpulin dulu ke array?"

JAWAB (ringkasan):
nodes = [] mengumpulkan semua pointer node Linked List
ke array sementara. Ini diperlukan karena Shell Sort butuh
akses acak ke elemen ke-i dan ke-(i+gap), sedangkan Linked
List tidak punya random access O(1). Dengan pointer di array,
akses O(1) bisa dilakukan. Swap dilakukan pada data di dalam
node bukan pointer-nya, sehingga struktur Linked List tetap.

----------------------------------------------------------------

[Claude Sonnet 4.6]
PROMPT:
"Bagaimana cara implementasi Shell Sort pada Linked List?
Kan Linked List tidak punya random access seperti array."

RESPONS (ringkasan):
Kumpulkan semua pointer node ke array temporary O(n),
lakukan Shell Sort pada array dengan swap data (bukan pointer),
hasilnya otomatis mencerminkan urutan di Linked List.
Struktur pointer Linked List tidak diubah sama sekali.

----------------------------------------------------------------

[GPT-5.5]
TANYA:
"dummy = LLNode di _merge_descending itu gunanya apa?
kenapa harus pakai node dummy?"

JAWAB (ringkasan):
Node dummy (sentinel) dipakai sebagai titik awal hasil merge
sementara. Tanpanya, kita perlu if-else khusus untuk
menentukan head hasil merge. Dengan dummy, kita selalu
sambungkan ke dummy.next dan di akhir return dummy.next
untuk melewati dummy itu sendiri. Teknik umum untuk
menyederhanakan logika merge pada Linked List.

----------------------------------------------------------------

[Claude Sonnet 4.6]
PROMPT:
"Gimana cara implementasi Merge Sort pada Linked List
tanpa mengconvert ke array Python dulu?"

RESPONS (ringkasan):
Murni dengan pointer manipulation:
1. Split: slow/fast pointer cari tengah lalu putus jadi dua
2. Rekursif sort dua bagian
3. Merge: gabung dua list terurut dengan sentinel node
Tidak perlu convert ke array sama sekali.

----------------------------------------------------------------

[SESI 3 — Debugging & Pertanyaan Lanjutan Sorting]

[GPT-5.5]
TANYA:
"waktu jalanin test sorting dapat error:
AssertionError: assert [14, 14, 7] == [21, 14, 7]

JAWAB (ringkasan):

----------------------------------------------------------------

[Claude Sonnet 4.6]
PROMPT:
"Merge Sort ku kadang hasilnya benar, kadang salah. Tidak

RESPONS (ringkasan):

tengah untuk benar-benar memutus dua bagian.

----------------------------------------------------------------

[Claude Sonnet 4.6]
PROMPT:
"Kenapa hasil benchmark Shell Sort kadang lebih cepat dari
Merge Sort padahal Big-O Merge Sort lebih baik?"

RESPONS (ringkasan):
Big-O mengabaikan konstanta. Shell Sort in-place tanpa
overhead rekursif. Untuk n kecil, konstanta Shell Sort
yang kecil bisa mengalahkan keunggulan asimptotik Merge Sort.

ANGGOTA SEMUA — Analisis Hasil Benchmark vs Teori
================================================================

[SESI BERSAMA — Diskusi Hasil Eksperimen Runtime]

[Claude Sonnet 4.6]
PROMPT:
"Kami sudah jalanin benchmark.py dan dapat hasil tabel
runtime untuk N=20, N=80, N=300. Tapi bingung cara
bacanya dan gimana cara menghubungkan ke teori Big-O
yang sudah kami pelajari. Bisa bantu analisis?"

RESPONS (ringkasan):
Cara membaca tabel benchmark: lihat rasio waktu antar N.
O(1) -> waktu hampir konstan. O(log n) -> naik sangat lambat.
O(n) -> naik linear. O(n2) -> naik 4x saat N naik 2x.
Bandingkan rasio empiris dengan prediksi teori.

----------------------------------------------------------------

[Claude Sonnet 4.6]
PROMPT:
"BST insert acak N=20=0.000089s, N=80=0.000412s,
N=300=0.001823s. Sedangkan insert terurut N=20=0.000095s,
N=80=0.000687s, N=300=0.004521s. Kenapa insert terurut
jauh lebih lambat di N=300?"

RESPONS (ringkasan):
Bukti empiris worst-case BST. Insert acak: rasio 300/20 ≈ 20x
untuk 15x lipat N -> mendekati O(n log n) total. Insert terurut:
rasio ≈ 47x -> mendekati O(n2) total. Gap semakin lebar
seiring N — persis prediksi teori O(log n) vs O(n) per operasi.

----------------------------------------------------------------

[GPT-5.5]
TANYA:
"kami bingung kenapa BFS graph hasilnya jauh lebih cepat
dari yang kami ekspektasikan. N=300 cuma 0.000312s.
apa ini normal?"

JAWAB (ringkasan):
Normal, karena graf yang dihasilkan sparse — tidak semua 300
buku terhubung satu sama lain. E (jumlah edge) jauh lebih
kecil dari V2 sehingga O(V+E) mendekati O(V) dalam kasus ini.
BFS terasa hampir linear terhadap V. Jika jumlah transaksi
ko-pinjam ditambah hingga setiap buku terhubung ke banyak
buku lain, barulah BFS terasa lebih lambat secara proporsional.

----------------------------------------------------------------

[Claude Sonnet 4.6]
PROMPT:
"Hasil Shell Sort N=20=0.000021s, N=80=0.000142s,
N=300=0.001876s. Merge Sort N=20=0.000018s, N=80=0.000098s,
N=300=0.000934s. Kenapa Merge Sort lebih cepat di N=300
tapi hampir sama di N=20?"

RESPONS (ringkasan):
Fenomena crossover point. Di N kecil, konstanta lebih dominan
dari Big-O — Shell Sort in-place tanpa overhead rekursif bisa
menang. Di N=300: 300^1.5 ≈ 5196 operasi vs 300xlog2(300) ≈ 2430
— Merge Sort 2x lebih efisien, cocok dengan rasio empiris.
